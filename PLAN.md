# Plan: Blazor WASM Bridge Bidding System Viewer

## Goal

Build a .NET Blazor WebAssembly app to browse the full bridge bidding system from two source HTML files:
- `System_ania.html` — the opening system (11 top-level sections, ~10 000 lines)
- `dwustronny_ania.html` — competitive bidding (20 top-level sections, ~5 000 lines)

Mode: reference tree viewer (clean, interactive, collapsible). Polish UI. Both files covered.

---

## Key Technical Facts — HTML Structure

- **Arrow SVGs** (expand chevron on branch nodes) have `class="arrow arrow--open"` and path `M192 128l128 128-128 128z` — **must be skipped**, not treated as suit symbols. Critical parsing trap.
- **Branch nodes**: `<li role="treeitem" class="tree-branch-wrapper">` — label is in the `<span>` that comes *after* the arrow SVG child.
- **Leaf nodes**: `<li role="none" class="tree-leaf-list-item">` — label is in the inner `<span>` of the inner `<div role="treeitem">`.
- **Suit SVG path prefixes** (confirmed in both files):
  - ♥ Heart → `M480.25 156.355`
  - ♠ Spade → `M458.915 307.705`
  - ♦ Diamond → `M431.76 256`
  - ♣ Club → `M477.443 295.143`
- **"BA"**, **"pas"**, **"x"**, **"xx"** — all plain text, no SVG.
- All source nodes start `aria-expanded="true"` — default state should be all-expanded.

---

## Solution Overview

1. **Generic converter CLI** (`Bridge.Converter`): parses any ARIA-tree HTML → structured JSON. SVG-to-symbol mapping is an external `suits.json` config, not hardcoded — usable with other bridge system files.
2. **Blazor WASM app** (`Bridge.App`): loads the generated JSON and renders a collapsible, searchable tree.

---

## Data Model

```
BidNode  { Id, Label, IsLeaf, List<BidNode> Children }   ← JSON-serialized
BridgeDocument { SourceFile, ConvertedAt, TopLevelCount, List<BidNode> Nodes }

Runtime only (not in JSON):
BidNode.IsExpanded  ← bool, defaults to true on load
```

### Phase 2 — Generic Converter CLI *(independent of Phase 3+)*

2. Add **HtmlAgilityPack** NuGet to `Bridge.Converter`.
3. Create `suits.json` default config:
   ```json
   {
     "svgClassToSkip": "arrow",
     "pathMappings": {
       "M480.25 156.355": "♥",
       "M458.915 307.705": "♠",
       "M431.76 256": "♦",
       "M477.443 295.143": "♣"
     }
   }
   ```
4. Implement `SvgResolver`: given an `<svg>` element — skip if `class` contains `"arrow"`, otherwise look up `d=` path prefix in mappings → return symbol string or `"?"` for unknown paths.
5. Implement `AriaTreeParser.Parse(IHtmlDocument, SvgResolver)`:
   - Start at `<ul class="tree">`, iterate top-level `<li>` elements.
   - **Branch** (`class="tree-branch-wrapper"`): label = text of the `<span>` after the arrow SVG; recurse into `<ul role="group">`.
   - **Leaf** (`role="none" class="tree-leaf-list-item"`): label = text of `<span>` inside the inner `<div role="treeitem">`.
   - For both: replace each `<svg>` child using `SvgResolver`; concatenate text nodes.
   - Assign stable positional IDs (e.g. `"1"`, `"1.2"`, `"1.2.3"`).
6. `Program.cs` CLI: parse args `--input <file>` `--output <file>` `[--suit-map suits.json]` `[--pretty]`; print summary (node counts per level) after conversion.
7. Run converter on both files → `Bridge.App/wwwroot/data/system.json` and `dwustronny.json`. Verify: 11 and 20 top-level nodes respectively.

**Output JSON shape:**
```json
{
  "sourceFile": "System_ania.html",
  "convertedAt": "2026-05-09T...",
  "topLevelCount": 11,
  "nodes": [
    {
      "id": "1",
      "label": "1♣ - 12+ bal, 15+ clubs or 18 any",
      "isLeaf": false,
      "children": [ ... ]
    }
  ]
}
```

16. `SearchBar.razor`: text input with 300ms debounce; on search — recursively filter nodes (case-insensitive `Contains` on `Label`); auto-set `IsExpanded = true` on all ancestors of matching nodes; highlight matched text; clear button; show match count ("Znaleziono: N").
17. **Rozwiń wszystko / Zwiń wszystko** buttons at the top of each page, calling `TreeView.ExpandAll()` / `TreeView.CollapseAll()`.

## Decisions

- **Blazor WebAssembly** — runs offline in browser, no server required.
- **JSON pre-conversion** — cleaner than runtime HTML parsing in WASM.
- **Generic converter** — file-agnostic; any ARIA-tree HTML + custom `suits.json` config works.
- **No shared project** — `BidNode` POCO duplicated to avoid cross-project reference complexity.
- **No CSS framework** — keeps bundle small and load fast.
- **Start all nodes expanded** — matches source HTML; user can collapse.
- **Unicode suit chars** — simpler than embedded SVGs; styled red/black via CSS.
- **Polish UI** — matches source content language.

## Out of Scope (v1)
